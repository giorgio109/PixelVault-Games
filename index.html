Arquitectura 4+1 de PixelVault Games

Las cinco vistas del modelo de Kruchten, especificadas en PlantUML. Esta aplicación implementa las clases de la Vista 2 y los componentes de la Vista 4.

Vista 1: Escenarios (+1)

Casos de uso que integran las otras cuatro vistas. Muestra qué hace cada actor (Cliente, Vendedor / Caja y Administrador) con los requerimientos RF1 a RF4: catálogo, ventas, arriendos con multa y gestión VIP.

Vista 2: Lógica

Modelo de dominio del sistema. Las clases Producto, Cliente, Arriendo, Venta y DetalleVenta se implementan en el código de esta web con los mismos nombres, atributos y métodos (verificarStock, calcularMulta, aplicarDescuentoVIP, calcularImpuestos).

Vista 3: Procesos

Comportamiento dinámico del arriendo: verificación de stock, descuento VIP del 10%, y en la devolución el cálculo de multa ($1.500 por día de atraso) y la acumulación de puntos.

Vista 4: Desarrollo

Organización del software en capas: Frontend (Web UI y Módulo Arriendos), Backend (API Gateway, Servicio Catálogo y Servicio Arriendos) y datos. En esta web, los servicios se simulan en memoria.

Vista 5: Física (Despliegue)

Infraestructura donde corre el sistema: navegador con la SPA, servidor de aplicaciones Node.js / Express y servidor de base de datos PostgreSQL, conectados por HTTPS y TCP/IP.
